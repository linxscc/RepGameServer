# 花色、羁绊/法宝分工、天象（局势系统）设计

日期：2026-11-07　状态：已确认（2026-11-07）。先模拟，效果不好再调整

## 1. 意图

现在商店里的卡只有"费用档"一个维度，同一张卡在任何局面下价值都差不多，玩法容易固化。参考小丑牌：**同一张卡，花色不同，在不同局面下价值天差地别**。

整体原则（用户原话整理）：

- 游戏简单，但每局可玩性很高。
- **组合系统负责创造可能性**：羁绊 + 花色 + 法宝之间有相互作用。
- **局势系统负责迫使玩家探索不同可能性**：局面变化让玩家改变对这些效果的选择，不能一套阵容打到底。

### 目标

- 每张卡有花色，花色在实际对局中起作用（主要通过法宝）。
- 羁绊只给数值，法宝给特殊效果，分工清楚。
- 加入"天象"：掷骰决定的负面效果，周期性出现，迫使转型。
- 每一步都用模拟器（`GoServer/tools/balance`，跑真实规则引擎 + bot）验证。

### 不做（本期）

- 不新增费用档（不加 4 费卡）。
- 不改星级、合成三张升一星的基本规则。
- 不做玩家手动改变卡牌颜色的操作界面（如需要，后续用法宝实现）。

### 失败标准（即使能跑也算失败）

- 规则变复杂到玩家需要读说明才能玩：卡面上看不懂自己是什么花色、天象说了什么。
- 某个花色流派或某条天象在模拟中胜率显著失衡（偏离 50% 超过 ±8 个百分点）。
- 天象让某些阵容"完全打不了"，而不是"需要调整"。
- 合成因为颜色变得明显更难（3★ 产出率明显下降）。

## 2. 花色

### 2.1 模型（用户决定）

- **神 / 鬼由卡牌种类决定**：每个系（line）固定属于神或鬼。
- **每一张卡再分红 / 黑两种颜色**，颜色属于这一张卡（卡实例），不属于卡种。
- 四种花色：红神、黑神、红鬼、黑鬼。

### 2.2 神鬼分配（Claude 的草案，用户可改）

按费用档平均分配，保证每个费用档神鬼各半：

| 费用 | 神 | 鬼 |
|---|---|---|
| 1 费 | 黄巾力士、木鱼沙弥、炉精 | 木魅、稻草精、书蠹 |
| 2 费 | 参娃、金蟾 | 墨灵、泥偶 |
| 3 费 | 鬼差（阴司公差，属神职） | 阴兵 |

配置：`chess_lines.yaml` 每个系加 `kind: god | ghost`，启动时校验。

### 2.3 卡池（用户决定）

- 每种卡数量翻倍：1 费 13→26、2 费 11→22、3 费 9→18。
- **红黑各占一半**，卡池按（系, 颜色）分别计数。
- 商店每个卡位抽到系之后，再从该系剩余的红/黑中按剩余数量加权抽颜色。商店卡位带颜色，买到的就是这个颜色。
- 卖出卡时归还到对应（系, 颜色）的卡池；合成卡卖出按其包含的原始卡数归还（颜色见 2.4）。

### 2.4 合成（用户同意 Claude 的方案，先跑模拟看效果）

- 同系同星 3 张即可合成，**不要求同色**。
- 合成结果的颜色 = 3 张中较多的颜色（3 张必定分出多数）。
- 合成卡卖出归还卡池时，按"结果颜色"归还全部张数（简化处理，Claude 的决定）。

**模拟要回答的问题**：

1. 与当前版本（卡池未翻倍、无花色）相比，3★ 产出数量和出现回合的变化。卡池翻倍会让合成更容易，预计需要调低卡池或其他数值。
2. 对比方案 B："必须同色才能合成"。看 3★ 产出率掉多少，用来说明为什么选方案 A。
3. 纯色流派（只要一种颜色）能否成型：一局中玩家能凑出多少张同色出阵卡。

### 2.5 卡面显示

- 卡面上用一个"神"或"鬼"字标出花色，字的颜色就是卡的颜色：红用朱砂红（`Theme.Red`），黑用墨黑（`Theme.Ink`）。
- 位置：卡面左下角、战力徽章上方（Claude 的决定，实现时如与现有元素冲突可调整）。
- 商店卡、出阵卡、备战卡、结算过场里的卡、对手阵容弹窗都要显示。
- 卡牌提示框里加一行"花色：红神"。

## 3. 羁绊与法宝分工（用户决定）

### 3.1 羁绊：只加数值

羁绊只允许三种数值：`points_per_card`（每张出阵卡 +战力）、`add_mult`（+气势）、`times_mult`（×气势）。其余现有修正项（`gold_per_merge`、`merged_bonus_points`、`free_refresh`、`xp_per_round`、`extra_slots`、`retrigger_left`）从羁绊中移除，效果迁移到法宝（见 3.2）。

羁绊改后草案（数值由模拟调整）：

| 羁绊 | 档位 | 效果 |
|---|---|---|
| 天工（行当） | 2 / 3 | +4 / +10 气势 |
| 文墨（行当） | 2 / 3 | +2 / +6 气势（不变） |
| 方外（行当） | 2 / 3 | 每张出阵卡 +3 / +8 战力（原 3 档的法宝额外触发不再放在羁绊里） |
| 敕令（行当） | 2 / 3 | 气势 ×1.3 / ×2（不变） |
| 山野（出身） | 2 / 4 | 每张出阵卡 +2 / +6 战力（不变） |
| 市井（出身） | 2 / 4 | +3 / +9 气势 |
| 庙堂（出身） | 2 / 4 | 气势 ×1.2 / ×1.6 |

羁绊**不看花色**。花色的作用完全由法宝和天象提供，避免卡面同时出现两套计数。

3★ 传说技能（`legend`）属于卡牌自身，本期不改。

### 3.2 法宝：特殊效果，分五类

法宝在配置里加 `category` 字段，用于宝库展示和后续按类抽取：

| 类别 | key | 说明 |
|---|---|---|
| 经济 | `economy` | 金币、利息、刷新、经验 |
| 成长 | `growth` | 永久累积的战力/气势 |
| 花色 | `suit` | 按自己出阵卡花色给加成 |
| 特攻 | `counter` | 按对手出阵卡花色生效 |
| 战术 | `tactic` | 位置、数量、星级、复制等其他效果 |

**现有 27 个法宝归类**（保留，不改效果）：

- 经济：出师礼 graduation、聚宝盆 treasure、精打细算 thrifty、存钱罐 piggy
- 成长：熔炉 furnace、账房 accountant、卧薪尝胆 grudge
- 战术：传家宝、宗师印、同门帖、门派令、杂家、家传绝学、独行侠、精兵简政、先锋旗、人多势众、后浪、殿后、藏锋、库房、乘胜追击、背水一战、乘风、文曲笔、铜镜、拓本

**从羁绊迁移来的效果，做成新的经济法宝**（名字为草案）：

| 名字 | 效果 |
|---|---|
| 匠人契 | 每次合成 +1 金（每回合最多 3 次） |
| 市集牌 | 每回合第 1 次刷新免费 |
| 书院荐 | 每回合 +2 经验 |
| 扩建令 | 出阵格 +1 |
| 百炼（成长类） | 合成出的卡永久 +3 战力（原天工 3 档） |

（与已有的"出师礼：每次合成 +1 金"重复的，合并为一个。原市井 4 档"前 3 次刷新免费"不保留，只留市集牌的 1 次。以上取舍是 Claude 的决定。）

**触发次数**（用户决定）：不新增"触发次数"数值。现有法宝和卡牌技能里已有的重复触发效果（家传绝学、天师 3★ 技能的 `retrigger_left`）保持不变，不额外增加。

**新增花色法宝**（约 8 个，名字与数值为草案）：

| 名字 | 效果 |
|---|---|
| 朱砂 | 每张红色出阵卡 +3 气势 |
| 松烟墨 | 每张黑色出阵卡 +15 战力 |
| 神龛 | 神卡在逐卡阶段战力 ×2 |
| 百鬼夜行 | 出阵中鬼卡 ≥4 张时，气势 ×2 |
| 一色 | 出阵卡全部同色（至少 3 张），气势 ×3 |
| 阴阳鱼 | 红黑张数相等（各至少 2 张），气势 ×2 |
| 四象 | 出阵中四种花色齐全，+20 气势 |
| 赤化 | 合成出的卡总是红色（经济/构筑辅助，让纯色流派更容易成型） |

**新增特攻法宝**（约 5 个，需要读取对手本回合出阵）：

| 名字 | 效果 |
|---|---|
| 照妖镜 | 对手每张鬼卡在其逐卡阶段战力 −30% |
| 破神符 | 对手每张神卡在其逐卡阶段战力 −30% |
| 克色 | 对手出阵中哪种颜色更多，自己该颜色的卡每张 +4 气势 |
| 斩首 | 对手最左边那张卡战力归零 |
| 反客为主 | 对手的花色法宝每有一个，自己 +5 气势 |

特攻法宝需要计分时同时看到双方的出阵：计分接口要能拿到对手本回合锁定的阵容（双方都已就绪后才计分，不存在信息顺序问题）。结算过场中，特攻效果显示在被影响一方的步骤里，来源标注为对手的法宝名。

**法宝总数**：现有 27 − 1（合并重复）+ 4 + 8 + 5 ≈ 43。新增法宝需要图标，交给 Codex 按现有 27 个的风格生成。

**宝库按类别抽取**：每次三选一尽量来自不同类别（Claude 的决定），保证每次都有"经济 / 构筑 / 应对"的取舍。

## 4. 天象（局势系统）

### 4.1 节奏（用户决定）

- 从**第 6 回合**开始，每 **5 回合**掷一次骰：第 6、11、16、21、26 回合。
- 每条天象生效 **6 回合**，所以每次换天象时会有 1 个回合两条同时生效（如第 11 回合：第 6 回合的天象最后一回合 + 第 11 回合的新天象）。
- 天象是**负面效果**，作用于对局双方。

### 4.2 掷骰方式（用户决定，细节为 Claude 的决定）

- **每位玩家拥有一个六面骰**。进入天象回合的准备阶段开始时，双方各自选择**掷或不掷**（限时，超时视为不掷）。双方的选择互不可见，都选完后同时揭晓。
- 天象由**双方骰子点数相加**决定，**不掷的一方点数记为 0**：
  - 双方都掷：2~12，中间点数最常见。
  - 只有一方掷：1~6。
  - 双方都不掷：系统替双方各掷一次（2~12），避免双方都不掷就没有天象（Claude 的决定）。
- 不掷是策略选择：天象表上 1~6 和 7~12 的天象不同，玩家可以根据自己的阵容决定掷不掷，把结果往对自己影响小的方向推。
- 没有重掷。
- 新天象与仍在生效的天象相同时，按点数顺延到下一条。
- 客户端：屏幕中央显示"掷骰 / 不掷"两个按钮 → 双方揭晓（骰子翻滚，不掷的一方显示空骰）→ 点数相加 → 天象名称与效果说明浮现 → 收到 HUD 的天象栏。
- 机器人：根据自己阵容对各天象的受损程度，估算掷与不掷的期望损失，选损失小的。

### 4.3 天象表草案

覆盖花色、神鬼、经济、商店、阵容五个方面：

表中概率是双方都掷时的概率；只有一方掷时，点数 1~6 各 1/6。

| 点数 | 概率 | 天象 | 方面 | 效果 |
|---|---|---|---|---|
| 1 | 仅一方不掷时 | 地动 | 阵容 | 备战席格数 −2 |
| 2 | 2.8% | 天狗食日 | 神鬼 | 神卡战力 ×0.4 |
| 3 | 5.6% | 百鬼退散 | 神鬼 | 鬼卡战力 ×0.4 |
| 4 | 8.3% | 赤月 | 花色 | 红色卡战力 ×0.6 |
| 5 | 11.1% | 墨雨 | 花色 | 黑色卡战力 ×0.6 |
| 6 | 13.9% | 荒年 | 经济 | 每回合基础收入 −2 |
| 7 | 16.7% | 闭市 | 商店 | 刷新费用 +1 |
| 8 | 13.9% | 苛税 | 经济 | 不产生利息 |
| 9 | 11.1% | 断货 | 商店 | 商店卡位 −1 |
| 10 | 8.3% | 窄道 | 阵容 | 出阵格 −1 |
| 11 | 5.6% | 失和 | 羁绊 | 所有羁绊生效所需数量 +1 |
| 12 | 2.8% | 天地异变 | 花色 | 出阵中占多数的那种花色，战力 ×0.5 |

### 4.4 组合系统与局势系统的相互作用

天象不只是惩罚，还要和法宝互动，让玩家在"顺着天象"和"对抗天象"之间做选择：

- 掷与不掷让玩家对天象有一定的控制。
- 新增 1 个"应对天象"的法宝（战术类，草案）：
  - **逆天**：每有一条生效中的天象，气势 ×1.5。
- 花色天象（赤月、墨雨、天狗食日、百鬼退散）直接打击当前主流花色，逼纯色流派要么转型，要么靠特攻/逆天硬扛。
- 经济和商店天象打击"拖经济"的打法，逼玩家提前用钱。

## 5. 协议与客户端

- `Card` 加 `color`（红/黑）；`LineInfo` 加 `kind`（神/鬼）；`ShopSlot` 加 `color`。
- `MatchState` 加生效中的天象列表（key、名称、说明、剩余回合）和本回合掷骰结果（双方点数，不掷为 0）；新增玩家操作"掷 / 不掷"。
- `RelicInfo` 加 `category`。
- 结算步骤（ScoreStep）中，特攻法宝和天象造成的修正作为新的步骤显示，来源写法宝名或天象名。
- 客户端：卡面花色字、商店卡颜色、HUD 天象栏（显示名称和剩余回合，悬停看说明）、掷骰动画、法宝提示框显示类别。
- 机器人（`chessbot`）需要理解花色和天象：至少会按自己法宝偏好的花色买卡、会在天象下调整阵容，否则模拟结果不可信。

## 6. 实施顺序

每一步完成后跑模拟，结果给用户看，确认后再进行下一步：

1. **花色 + 卡池 + 合成**：服务端模型、配置、协议、卡面显示、bot 按颜色购买；模拟回答 2.4 的三个问题。卡池翻倍是起点，模拟显示合成太容易时**允许下调**（保持红黑各半，用户决定）。
2. **羁绊纯数值化 + 法宝分类 + 迁移法宝**：模拟各羁绊胜率与旧版对比。
3. **花色法宝 + 特攻法宝**：模拟各花色流派胜率。
4. **天象**：掷骰、天象表、客户端动画；模拟每条天象下各流派胜率变化，以及"有天象 vs 无天象"时阵容的多样性。
5. **新法宝图标**：交给 Codex 生成。

## 6.1 模拟的衡量方法（Claude 的决定）

- bot 增加几种流派：无花色基线、纯红、纯黑、神、鬼、特攻、经济。
- 主要指标：各流派在**所有流派混合循环对战**中的平均胜率；失败标准里的"±8 个百分点"指这个平均胜率。
- 天象的衡量：分别统计"某条天象生效期间"各流派的胜率变化，以及有天象和无天象时最终阵容的多样性（不同流派获胜的分布）。天象同时作用于双方，所以不看天象本身的胜率。

## 6.2 上线方式（Claude 的决定）

每个阶段做完、模拟通过后，服务端（RepServer）和客户端（main）同步推送上线，用户实际试玩。不做配置开关，不兼容旧客户端。
